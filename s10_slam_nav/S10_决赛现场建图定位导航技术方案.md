# S10 轮足机器狗决赛现场建图、定位与自主导航技术方案

> 版本：V1.0（比赛交付版）  
> 编制日期：2026-09-04  
> 目标赛事：GOAI 2026「具身未来」赛道——产业园区巡逻赛题决赛  
> 决赛日期：2026-09-22  
> 核心目标：以最小改造、最少依赖和可快速回退的方式，在 S10 实机上完成“现场建图—定位—自主导航—避障—到达全部指定点”的稳定闭环。

---

## 1. 方案结论

决赛不再沿用初赛 `first_ok` 的 MuJoCo 真值位姿和仿真控制接口。最终方案采用：

**双 Airy 激光雷达驱动 + 前雷达/IMU 适配 + Lightning-LM 建图定位 + 地图坐标系固定路线 + Pure Pursuit 跟踪 + 双雷达局部避障 + 安全指令仲裁 + S10 `/STEER` 控制。**

比赛运行时只启用定位，不在线修改地图；现场先人工遥控建图，地图保存后重新定位，再单独录制巡检路线。自主阶段由机器人独立完成路径跟踪、检查点切换、障碍判断与绕行，满足“自主导航”模式的技术定义，目标按 **1.4 模式系数**计分。

本方案的关键取舍如下：

| 项目 | 决策 | 原因 |
|---|---|---|
| 建图定位 | Lightning-LM | 已有 Deep Robotics 适配代码，支持在线建图、保存地图和在线定位 |
| LIO 输入 | 前 Airy 点云 + 前 Airy IMU | 单雷达时间链最简单，避免双雷达点级时间戳混合破坏去畸变 |
| 双雷达用途 | 局部障碍检测与可视化 | 获得前后视野，不影响 LIO 主链稳定性 |
| 全局导航 | 地图坐标系固定路线 | 赛道固定、交付周期短，较通用全局规划器更易稳定复现 |
| 路径跟踪 | Pure Pursuit + 转向优先限速 | 算法简单、参数少、对连续采样路线稳定 |
| 局部避障 | 扇区空隙选择 + 减速/停车 | 满足自主决策与避障要求，复杂度低且便于现场调参 |
| 底盘控制 | 仅发布 `/STEER` | 复用 S10 现有 RL 运动控制，不改底层策略 |
| 状态切换 | 人工站立、进入 RL 模式 | 降低自动状态切换风险，不影响自主导航主体 |
| 第一版范围 | 不引入 Nav2、FAST-LIVO2、语义/VLM、完整三维规划 | 控制依赖、联调量和现场不确定性 |

## 2. 比赛目标与判定边界

### 2.1 决赛任务理解

根据决赛介绍，机器人需要在真实场地中完成全部指定点巡逻。成绩由完成时间与模式系数共同决定：

```text
折算成绩 = 完成时间（秒） / 模式系数

遥控：1.0
自主跟随：1.3
自主导航：1.4
```

自主导航要求机器人自主完成导航、决策和避障。因此，本方案不能只做无感知的速度脚本或纯时间回放，必须至少具备：

1. 基于现场地图的实时定位；
2. 地图坐标系中的路线和检查点管理；
3. 自主检查点切换和速度决策；
4. 对临时障碍物的减速、停车或绕行；
5. 定位异常、节点失活和通信异常时的安全停车。

### 2.2 交付优先级

按比赛收益和失败代价，优先级定义为：

1. **安全且不偏离路线；**
2. **全部指定点到达；**
3. **连续多次可重复完成；**
4. **在稳定基础上逐步提速；**
5. **增加复杂功能。**

最短时间不是一开始把速度参数调到最大，而是减少定位丢失、错误绕行、碰撞、漏点和人工重启造成的长尾时间。

### 2.3 首版不做的内容

以下内容不进入 P0 比赛闭环：

- Nav2 全栈接入；
- FAST-LIVO2 与 Lightning-LM 双路线并行维护；
- 在线重建地图；
- 完整三维地形可通行性分析；
- 负障碍深度学习检测；
- VLM/VLA、3D Gaussian Splatting 或语义巡检；
- 自动切换轮式/足式步态；
- 复杂动态障碍预测；
- 自动探索建图。

这些功能只有在 P0 连续稳定通过后才评估加入。

## 3. 现有资料与代码评估

### 3.1 S10 实机代码

当前工程已经具备以下基础：

- Ubuntu 24.04、ROS 2 Jazzy；
- S10 实机 RL 运动控制部署；
- `/STEER` 控制接口；
- 前后两台 RS-LiDAR-AIRY 驱动配置；
- 双雷达点云合并节点；
- S10 URDF 和传感器安装参数；
- DDS 消息及底盘通信代码。

现有 `/STEER` 的归一化量到物理速度的对应关系为：

```text
vx = 1.5 × steer.x       m/s
vy = 0.5 × steer.y       m/s
wz = 0.6 × steer.yaw     rad/s
```

因此自主导航输出必须统一做限幅和斜率限制：

```text
steer.x   = clamp(vx / 1.5, -1, 1)
steer.y   = clamp(vy / 0.5, -1, 1)
steer.yaw = clamp(wz / 0.6, -1, 1)
```

### 3.2 `first_ok` 初赛代码

`first_ok` 的可复用部分：

- 航点序列和状态机思想；
- 朝向误差计算；
- 大角度误差时降低前进速度；
- 到点判定和结束停车逻辑。

不能直接复用的部分：

- MuJoCo 真值 `/BASE_POSE`；
- 仿真航点 `/TRACK_WAYPOINTS`、`/TRACK_ACTIVE_INDEX`；
- `/CMD_VEL`、`/CMD_MODE` 仿真接口；
- teleport/reset 等仿真专用能力；
- 仅面向目标点、没有局部避障的控制方式。

决赛版需将“真值位姿”替换为 Lightning-LM 的地图定位，将仿真控制替换为 `/STEER`，并增加实机安全闭环。

### 3.3 上游组件

本地已取得并检查的关键组件如下：

| 组件 | 建议固定版本 | 用途 |
|---|---|---|
| `lightning-lm-deep-robotics` | `31ce5190bb2dc9c8be99a572fe2413380ad60cd6` | 激光惯性建图和定位 |
| `rslidar_sdk` | tag `v1.5.19`，commit `78d2abb...` | Airy 点云与 IMU 驱动 |
| `rs_driver` 子模块 | `4eeadace...` | RoboSense 底层解析 |
| `rslidar_msg` | `fe8a95cb242bd294cc3d5e3422f2093fb49a56ee` | 雷达 ROS 消息 |
| `deep-robotics-msg` | 本地完整仓库 | Deep Robotics 消息参考 |

`FAST-LIVO2` 不作为当前主方案依赖，避免同时承担两套 LIO 的编译、坐标系和参数风险。

### 3.4 现有代码中的关键风险

| 风险 | 影响 | 必须采取的措施 |
|---|---|---|
| rslidar SDK 默认输出 `XYZI` | Lightning RoboSense 处理器需要 `XYZIRT`，可能无法读取 ring/timestamp | 编译前将 `POINT_TYPE` 固定为 `XYZIRT` |
| 驱动默认关闭点云变换 | YAML 中安装位姿可能不生效 | 启用 `ENABLE_TRANSFORM` |
| 驱动默认关闭 IMU 解析 | Lightning 无 IMU 输入 | 启用 `ENABLE_IMU_DATA_PARSE` |
| Airy IMU 不提供有效 orientation | 错误使用姿态会导致初始化异常 | Lightning 设置 `use_imu_orient: false` |
| 点云被旋转但 IMU 未同步旋转 | LIO 的点云与惯性坐标不一致 | 增加 `s10_imu_adapter` 同步旋转角速度和加速度 |
| 合并点云只有帧级配对 | 两帧点内时间基准不同 | 合并点云禁止作为 Lightning 输入 |
| `/STEER` 最后一条命令会持续 | 上层进程崩溃后机器人仍可能运动 | 上层 deadman + 底层 DDS 超时清零双保险 |
| Lightning 定位置信度为硬编码 | 无法直接用作安全判断 | 独立健康监控，检查新鲜度、跳变和数据流 |
| Lightning 定位启动初值代码存在覆盖风险 | 可能忽略 YAML 的初始位姿 | 修正初始化逻辑并做已知起点测试 |

## 4. 总体系统架构

```mermaid
flowchart LR
    FPC[前 Airy 点云 XYZIRT] --> LIO[Lightning-LM\n建图或定位]
    FIMU[前 Airy IMU] --> ADP[s10_imu_adapter\n坐标旋转/有效性标记]
    ADP --> LIO
    LIO --> POSE[地图位姿 / TF]
    POSE --> ROUTE[s10_route_manager\n路线与检查点]
    ROUTE --> FOLLOW[s10_route_follower\nPure Pursuit]

    FPC --> OBS[s10_obstacle_guard]
    RPC[后 Airy 点云 XYZIRT] --> OBS
    OBS --> MUX[s10_command_mux]
    FOLLOW --> MUX
    POSE --> HEALTH[s10_health_monitor]
    ADP --> HEALTH
    HEALTH --> MUX
    MUX --> STEER[/STEER]
    STEER --> RL[S10 RL 底盘控制]
```

### 4.1 数据主链

```text
传感器 → 时间戳/坐标适配 → 建图或定位 → 地图位姿
地图位姿 + 固定路线 → 路径跟踪 → 期望速度
双雷达障碍检测 + 健康状态 → 指令仲裁 → /STEER → S10
```

### 4.2 运行模式

系统只允许三种互斥模式：

| 模式 | Lightning 节点 | 路线控制 | 用途 |
|---|---|---|---|
| `sensor_check` | 不启动 | 不启动 | 传感器和坐标检查 |
| `mapping` | `run_slam_online` | 不发布运动指令 | 人工遥控建图 |
| `navigation` | `run_loc_online` | 启用 | 比赛自主导航 |

严禁同时运行在线建图和在线定位，避免 TF、地图和位姿话题冲突。

## 5. 传感器、时间戳与坐标系

### 5.1 雷达话题

| 设备 | 点云话题 | IMU 话题 | 规划用途 |
|---|---|---|---|
| 前 Airy | `/rslidar_front/points` | `/rslidar_front/imu` | LIO 主输入、前向避障 |
| 后 Airy | `/rslidar_rear/points` | `/rslidar_rear/imu` | 后向/侧向障碍检测 |
| 双雷达合并 | `/LIDAR/POINTS_MERGED` | 无 | RViz 与局部障碍检测备选 |

Lightning-LM 的 RoboSense 点类型要求为：

```text
float32 x
float32 y
float32 z
float32 intensity
uint16  ring
float64 timestamp
```

启动前必须用 `ros2 topic echo --once` 或自检节点验证字段名称、类型和顺序，不能只确认“话题有数据”。

### 5.2 驱动编译要求

`rslidar_sdk` 必须满足：

```cmake
set(POINT_TYPE XYZIRT)
set(ENABLE_TRANSFORM ON)
set(ENABLE_IMU_DATA_PARSE ON)
```

由于上游 `CMakeLists.txt` 可能用普通变量覆盖命令行传入值，不能只依赖 `colcon build --cmake-args -DPOINT_TYPE=XYZIRT`。比赛分支应直接补丁为缓存变量或固定为 `XYZIRT`，并在构建日志中确认最终值。

### 5.3 坐标系策略

建议统一使用以下坐标树：

```text
map
└── odom（如 Lightning 实际提供）
    └── base_link
        └── lidar_link
```

P0 为减少外参链复杂度，可将驱动输出的公共 `lidar_link` 定义为机体水平坐标系，并让点云安装变换直接输出到该坐标系。当前双 Airy 配置参考值为：

```yaml
front:
  x: 0.22341
  y: 0.0
  z: -0.0001
  roll: 0.0
  pitch: -1.5707
  yaw: -3.14159

rear:
  x: -0.22341
  y: 0.0
  z: -0.0001
  roll: 0.0
  pitch: -1.5707
  yaw: 0.0
```

这些参数必须通过实机 RViz 验证，不以配置文件存在作为正确依据。验证标准：

- 机器人静止时地面为连续平面；
- 正前方物体在点云的正前方；
- 左右移动时点云方向符合 ROS 右手坐标系；
- 前后雷达观察同一墙面时基本重合；
- 低速行走时墙面无明显双层和扭曲。

### 5.4 IMU 适配

驱动对点云应用安装旋转时，不会自动对 IMU 向量应用相同旋转。因此新增 `s10_imu_adapter`：

1. 订阅 `/rslidar_front/imu`；
2. 使用与前雷达点云相同的固定旋转矩阵，将 `angular_velocity`、`linear_acceleration` 旋转到 `lidar_link`；
3. 保留原始时间戳；
4. 发布 `/IMU`；
5. 设置 `orientation_covariance[0] = -1`，明确姿态不可用；
6. 检查时间戳单调性、消息间隔和异常跳变。

Lightning 配置：

```yaml
common:
  lid_topic: /rslidar_front/points
  imu_topic: /IMU

preprocess:
  lidar_type: 4
  scan_line: 32

mapping:
  use_imu_orient: false
```

具体 YAML 键名以当前 Lightning 分支为准，修改后必须通过启动日志确认参数确实加载。

### 5.5 时间同步要求

- 两台 Airy 使用雷达自身时钟时，必须确认时间源稳定且与 ROS 时间没有明显跳变；
- 前点云与前 IMU 应来源于同一设备时间链；
- `ts_first_point: true` 必须与 Lightning 对 timestamp 的语义一致；
- 录包检查点云帧间隔、点内 timestamp 范围和 IMU 时间是否覆盖整帧扫描；
- 禁止把仅按 100 ms 窗口配对后拼接的双雷达点云送入 LIO。

## 6. Lightning-LM 接入与必要补丁

### 6.1 使用方式

| 阶段 | 可执行程序 | 输入 | 输出 |
|---|---|---|---|
| 建图 | `run_slam_online` | 前 Airy 点云、适配 IMU | 地图、轨迹、里程计 |
| 保存 | `lightning/save_map` 服务 | 当前地图 | 地图目录 |
| 定位 | `run_loc_online` | 保存地图、前 Airy 点云、适配 IMU | `/lightning/odom`、TF、路径 |

地图路径一律使用绝对路径，避免 launch 工作目录变化导致加载失败。

### 6.2 P0 必修补丁

#### A. 空点云保护

RoboSense 处理代码在访问 `points[0]` 前增加空点云判断。否则驱动瞬时空帧会导致定位节点崩溃。

#### B. 定位初始位姿

修正 `run_loc_online.cc` 中配置对象复制后仍检查旧对象的问题，确保 YAML 中的 `use_init_pose` 和初始位姿实际生效。比赛采用固定起点时，初值应写入比赛配置并在每次启动后检查。

#### C. 定位健康状态

不得把当前硬编码的 `confidence=1.0`、`pose_is_ok=true` 当作真实质量指标。首版由 `s10_health_monitor` 至少检查：

- `/lightning/odom` 更新频率；
- 位姿消息最大延迟；
- 单帧平移和旋转跳变；
- 点云和 IMU 是否持续更新；
- TF 是否可查询；
- 当前位姿是否超出路线走廊。

#### D. `map → base_link` 统一

Lightning 默认可能发布到 `lidar_link`。路线跟踪必须明确使用机器人控制点 `base_link`。若 `lidar_link` 已定义在机体中心，可发布恒等静态变换；否则应用实际平移/旋转，不能混用两种位姿。

#### E. 依赖收敛

删除或条件化 `package.xml` 中实际未使用、现场系统缺失的 `scrubber_common`、`agibot_robot` 依赖。优先增加 headless 构建选项，避免比赛 AGX 因 Pangolin/OpenGL 环境导致构建或运行失败。

### 6.3 初始参数建议

以下参数只作为首轮起点，最终值以现场录包和重复测试为准：

| 参数 | 初值建议 | 调整依据 |
|---|---:|---|
| `point_filter_num` | 6 | CPU 占用与定位质量 |
| 体素尺寸 | 0.15～0.25 m | 场景结构密度和算力 |
| IMU 静止初始化 | 10～20 s | 启动后偏置稳定情况 |
| 定位输出最低频率 | ≥ 8 Hz | 控制闭环稳定性 |
| 位姿超时停车 | 0.30 s | 实测消息抖动 |
| 单帧平移跳变阈值 | 0.5 m | 正常最大速度和帧率 |
| 单帧航向跳变阈值 | 15° | 正常最大转速和帧率 |

## 7. 地图与路线生产流程

### 7.1 建图不是比赛运行的一部分

现场建图阶段由人工遥控，目标是得到可重复定位的静态地图。比赛运行阶段加载地图，只做定位和导航。

### 7.2 建图流程

1. 固定所有传感器安装件，标记螺丝位置，禁止建图后改变外参；
2. 启动传感器自检，确认字段、时间、频率和坐标方向；
3. 录制一段静止数据，等待 IMU 初始化 10～20 秒；
4. 启动 `run_slam_online`；
5. 人工以低速、平滑、小角速度行走完整赛道；
6. 对交叉口、相似长廊和指定点附近进行多角度观测；
7. 回到起点形成闭环；
8. 保存地图到带时间和版本号的绝对路径；
9. 停止建图节点，重新启动定位节点验证地图可加载；
10. 重走一圈检查重定位、重复性和局部地图匹配。

建图驾驶要求：

- 避免原地快速旋转；
- 避免贴墙过近；
- 在拐角处降低速度并扩大可见结构；
- 对玻璃、强反射、稀疏区域增加不同角度观测；
- 人员尽量远离雷达近场；
- 建图过程中同步录 rosbag，便于离线复现。

### 7.3 路线录制

路线不在 SLAM 建图过程中直接定稿。保存地图并重新启动定位后，再执行一次人工示教：

1. 机器人放在规定起点；
2. 确认定位稳定；
3. 沿允许路线人工行驶；
4. 以固定距离或固定时间采样 `map → base_link`；
5. 在每个指定点记录独立 checkpoint；
6. 对原始轨迹降采样和平滑；
7. 给检查点设置顺序、容差和必须到达标志；
8. 保存为 `route.yaml`；
9. 用 RViz 叠加地图检查路线是否穿墙、越界或切角。

这样可以避免 SLAM 闭环优化后，建图过程中记录的旧轨迹与最终地图产生偏差。

### 7.4 路线文件建议格式

```yaml
frame_id: map
route_name: final_route_v01
loop: false
max_corridor_error: 0.60

controller:
  lookahead: 0.90
  nominal_speed: 0.55
  max_speed: 0.80
  max_yaw_rate: 0.45
  goal_slow_radius: 1.20

checkpoints:
  - id: P01
    x: 1.20
    y: 0.35
    yaw: 0.00
    position_tolerance: 0.35
    yaw_tolerance_deg: 15
    required: true

path:
  - [0.00, 0.00, 0.00]
  - [0.30, 0.02, 0.01]
  - [0.60, 0.04, 0.02]
```

检查点容差必须根据现场判定规则调整。若比赛通过区域触发而不是精确姿态触发，内部容差仍应略严于官方判定范围。

## 8. 自主导航控制

### 8.1 路径跟踪

采用 Pure Pursuit：在路线中查找距离机器人前方一定距离的目标点，将其转换到 `base_link`，根据横向误差生成角速度。

核心逻辑：

```text
1. 找到当前位置在路线上的最近投影点
2. 沿路线向前查找 lookahead 目标点
3. 将目标点变换到 base_link
4. 计算曲率和期望角速度
5. 根据曲率、目标距离、障碍距离和定位质量决定前进速度
6. 输出归一化 /STEER
```

首轮参数建议：

| 参数 | 建议范围 |
|---|---:|
| 前视距离 | 0.8～1.2 m |
| 初始标称速度 | 0.4～0.6 m/s |
| 稳定后最高速度 | 0.8～1.0 m/s |
| 最大角速度 | 0.35～0.50 rad/s |
| 控制频率 | ≥ 20 Hz |
| 线速度加速度限制 | 0.4～0.8 m/s² |
| 角速度变化率限制 | 0.6～1.0 rad/s² |

在航向误差较大时继承 `first_ok` 的“转向优先”思想：

```text
|heading_error| > 60°：停止前进，只转向
30° < |heading_error| ≤ 60°：显著降低前进速度
|heading_error| ≤ 30°：按曲率和障碍距离调速
```

阈值通过实机转弯稳定性确定，不直接照搬仿真参数。

### 8.2 检查点状态机

| 状态 | 行为 | 退出条件 |
|---|---|---|
| `INIT` | 发布零指令，加载配置 | 配置、地图和路线有效 |
| `WAIT_LOCALIZATION` | 发布零指令，等待定位 | 连续稳定 N 帧 |
| `READY` | 等待裁判/操作员启动 | 收到启动信号 |
| `RUNNING` | 路径跟踪与检查点切换 | 完成、遇障或故障 |
| `BLOCKED` | 停车并尝试局部绕行 | 出现安全通道或超时 |
| `FINISHED` | 连续发布零指令 | 人工退出 |
| `FAULT` | 锁定零指令、报警 | 人工确认和重启 |

检查点切换使用“距离 + 穿越判定 + 最短驻留时间”组合，防止定位抖动造成重复触发或漏点。每到达一个检查点，应打印并持久化：

```text
checkpoint_id, 到达时间, 最小距离, 当前定位状态, 累计用时
```

### 8.3 路线走廊

计算机器人到参考路线的横向距离：

- 小于警戒阈值：正常运行；
- 超过警戒阈值：降低速度并增大回归权重；
- 超过最大阈值：立即停车，防止偏离规定路线。

初始建议警戒阈值 0.40 m、停车阈值 0.60 m，现场根据路线宽度和裁判边界调整。

## 9. 局部障碍检测与绕行

### 9.1 P0 能力边界

P0 不建立完整局部代价地图，采用双雷达 ROI 投影和扇区统计：

1. 将前后点云转换到 `base_link`；
2. 裁剪机器人自身、地面以下噪点和过高点；
3. 对机器人周围划分角度扇区；
4. 统计各扇区最近障碍距离和点数；
5. 计算当前路径方向是否被占用；
6. 若存在安全空隙，临时偏转目标方向；
7. 若没有安全空隙，停车等待；
8. 障碍消失后平滑回到原路线。

### 9.2 初始区域与阈值

以下值仅为现场调参起点：

| 项目 | 初始值 |
|---|---:|
| 前向检测长度 | 2.0 m |
| 侧向检测宽度 | 1.2 m |
| 有效高度范围 | 0.10～1.20 m |
| 紧急停车距离 | 0.60 m |
| 减速距离 | 1.20 m |
| 障碍消失确认 | 连续 5～10 帧 |
| 最大临时绕行偏移 | 不超过路线走廊 |

机器人本体包围盒和腿部运动区域必须从点云中剔除，避免将自身识别为障碍。

### 9.3 决策优先级

```text
急停/故障 > 路线越界保护 > 近障碍停车 > 局部绕行 > 正常路径跟踪
```

绕行不得突破规定路线走廊。如果障碍物完全封闭允许通道，系统应停车等待，不为追求完成时间冒险越界。

### 9.4 深度相机定位

赛题允许加装深度相机，但 P0 不依赖深度相机完成闭环。仅在下列实测问题出现时加入 D435i 或同类深度相机：

- Airy 对近距离低矮障碍存在明显盲区；
- 赛道存在雷达难以识别的细杆或透明材质；
- 存在必须处理的台阶边缘或负障碍。

加入后只作为近场安全传感器，不替换 Lightning 主定位链。

## 10. 指令仲裁与实机安全

### 10.1 `/STEER` 输出规则

只有 `s10_command_mux` 可以向 `/STEER` 发布。其他节点只发布内部期望指令，例如：

```text
/s10_nav/cmd_tracking
/s10_nav/cmd_avoidance
/s10_nav/emergency_stop
```

`s10_command_mux` 负责：

- 输入新鲜度检查；
- 状态优先级仲裁；
- 速度和角速度限幅；
- 加速度/变化率限制；
- 20～50 Hz 连续输出；
- 未收到上游指令 200～300 ms 后输出零；
- 退出、完成、异常时连续输出零指令。

### 10.2 底层超时保护

仅靠上层 mux 不足以覆盖 mux 自身崩溃。必须在 `DdsCommandInterface` 或其消费 `/STEER` 的最后一级增加单调时钟 watchdog：

```text
当前时间 - 最后有效 /STEER 时间 > 300 ms
→ forward_vel_scale = 0
→ side_vel_scale = 0
→ turning = 0
```

该补丁是实机上线前的阻断项。验证方法是在机器人低速运动时结束导航进程，确认 0.3 秒左右自动停下。

### 10.3 人工接管

- 站立、进入 RL 模式继续使用手柄；
- 自动导航只接管 `/STEER`；
- 保留硬件急停或底盘原生急停；
- 手柄接管信号优先级高于自主指令；
- 接管后必须将自主状态切到 `FAULT` 或 `PAUSED`，防止松开按键后自动恢复运动。

## 11. ROS 2 接口设计

### 11.1 主要订阅与发布

| 节点 | 订阅 | 发布/服务 |
|---|---|---|
| `s10_imu_adapter` | `/rslidar_front/imu` | `/IMU` |
| Lightning | `/rslidar_front/points`、`/IMU` | `/lightning/odom`、TF、`/lightning/path`、地图 |
| `s10_route_manager` | `/lightning/odom` | 路线、当前检查点、进度 |

### 11.2 QoS 建议

- 点云、IMU：Sensor Data QoS，`best_effort`、小队列；
- 位姿和控制：`reliable`，小队列，避免积压旧控制量；
- 路线和静态配置：`transient_local`；
- 急停：`reliable`，并由底层 watchdog 独立兜底；
- 所有控制决策使用消息时间戳和接收单调时间共同判断新鲜度。

## 13. 构建与部署策略

### 13.1 构建隔离

建议采用两个 overlay，降低 Lightning 第三方依赖对 S10 原工程的影响：

```text
s10_base_ws：S10、rslidar、消息、传感器适配、路线导航
lightning_ws：比赛补丁版 Lightning-LM
```

运行时按顺序 source：

```bash
source /opt/ros/jazzy/setup.bash
source /absolute/path/s10_base_ws/install/setup.bash
source /absolute/path/lightning_ws/install/setup.bash
```

若现场维护人员更熟悉单工作区，也可合并，但必须固定依赖版本并完整执行一次“全新目录从零构建”测试。

### 13.2 AGX 运行配置

- 使用最高性能电源模式并锁定风扇策略；
- 关闭 Lightning 可视化窗口，RViz 仅在调试时运行；
- 核心节点全部运行在 AGX 本机；
- 固定 `ROS_DOMAIN_ID` 和 DDS 网卡；
- 禁止依赖比赛现场无线网络完成定位控制；
- 记录 CPU、内存、温度和点云丢帧；
- 开机后先校验系统时间和传感器时间状态。

### 13.3 一键启动目标

比赛运行最终只保留三个操作：

```bash
./preflight_check.sh
./start_navigation.sh
./stop_all.sh
```

`preflight_check.sh` 失败时不得进入 READY 状态。检查内容包括：

- 雷达与 IMU 话题存在；
- 点云字段为 XYZIRT；
- 频率和时间戳合格；
- 地图和路线文件存在且校验通过；
- TF 完整；
- `/STEER` 无其他发布者；
- 磁盘空间、CPU 温度、DDS 配置正常；
- Lightning 进程和导航进程没有重复实例。

## 14. 现场操作流程

### 14.1 第一次到场

1. 测量并复核传感器安装；
2. 通电后只启动驱动，检查点云和 IMU；
3. 录制 3～5 分钟传感器包；
4. 静态检查点云漂移；
5. 人工低速直行、横移、转向，验证轴向；
6. 验证 `/STEER` 比例、正负方向和停止响应；
7. 杀死指令发布节点，验证底层 watchdog。

### 14.2 建图日

1. 完成传感器预检；
2. 建图并形成闭环；
3. 保存至少两个独立地图版本；
4. 重启整套系统加载地图；
5. 在起点、拐角、长廊和指定点验证定位；
6. 选择稳定地图作为 `final_map`，另一版本作为备份。

### 14.3 路线调试

1. 定位模式下人工示教；
2. 生成路线和检查点；
3. RViz 离线检查；
4. 以 0.3～0.4 m/s 首次自主运行；
5. 分段验证，再跑全程；
6. 检查全部指定点事件日志；
7. 连续成功后每次仅增加 0.1 m/s；
8. 出现一次定位异常或明显越界，回退到上一稳定速度。

### 14.4 比赛当天

1. 检查机械安装标记是否移动；
2. 开机、性能模式、DDS 和时间检查；
3. 启动驱动并静止完成 IMU 初始化；
4. 启动定位并等待稳定；
5. 手柄控制站立并进入 RL 模式；
6. 操作员确认 READY；
7. 裁判允许后触发 RUNNING；
8. 完成最后检查点后持续零指令；
9. 保存日志，不在比赛间隙随意修改多个参数。

## 16. 验收测试

### 16.1 传感器验收

- 前后点云稳定约 10 Hz；
- IMU 频率稳定，无长时间断流；
- PointCloud2 字段和类型完全匹配 XYZIRT；
- 点云与 IMU 时间戳单调，无明显回跳；
- 静止点云无持续明显旋转或平移；
- 前后点云在公共坐标系方向正确；
- 运动时无明显双墙和严重去畸变失败。

### 16.2 建图定位验收

- 在线建图连续运行完整一圈不崩溃；
- 地图服务成功保存并可在重启后加载；
- 固定起点连续 5 次启动均能得到正确位姿；
- 完整路线往返后位置误差初始目标 ≤ 0.30 m；
- 航向误差初始目标 ≤ 5°；
- 长走廊、拐角和指定点附近无频繁跳变；
- 任一位姿跳变或超时会触发零指令。

### 16.3 导航验收

- 无障碍全程连续 5 次完成；
- 所有 required checkpoint 到达率 100%；
- 无人工转向干预；
- 不超出规定路线走廊；
- 每次完成后机器人稳定停车；
- 路线时间方差可接受，无随机长时间停顿。

### 16.4 避障与安全验收

- 前方放置障碍后在设定安全距离前停车；
- 存在合规通道时可低速绕行并回归路线；
- 无合规通道时保持停车；
- 后退或侧移时后雷达保护有效；
- 杀死 `route_follower` 后 mux 清零；
- 杀死 `command_mux` 后底层约 0.3 秒清零；
- 雷达、IMU、定位任一关键话题超时后停车；
- 手柄接管立即覆盖自主指令。

所有数值阈值是首轮工程目标；若官方指定点半径或现场路线边界更严格，应以官方规则为上限重新设置。

## 17. 风险矩阵与回退策略

| 风险 | 概率 | 后果 | 预防 | 回退 |
|---|---|---|---|---|
| 点云不是 XYZIRT | 高 | LIO 无法正常处理 | 构建和启动双重字段检查 | 固定已验证二进制 |
| 点云/IMU 坐标不一致 | 高 | 地图畸变、定位发散 | IMU 适配器、轴向测试 | 使用已验证外参包 |
| Lightning 在 AGX/Jazzy 构建失败 | 中高 | 主链阻断 | 提前固定依赖、headless 构建 | 使用预编译镜像/安装目录 |
| 定位初值不生效 | 高 | 起步位姿错误 | 修补初始化代码、固定起点复测 | 人工重启并加载已知初值 |
| 双雷达合并用于 LIO | 高 | 去畸变错误 | 架构上禁止 | 立即切回单前雷达 |
| `/STEER` 发布者崩溃后续跑 | 高 | 安全事故/成绩取消 | 上下层双 watchdog | 硬件急停 |
| 相似长廊定位跳变 | 中 | 偏航、漏点 | 建图多视角、路线走廊保护 | 停车，重新从已知起点启动 |
| 临时障碍完全封路 | 中 | 无法完成 | 停等和简单绕行 | 按赛场规则请求处理，不越界 |
| 外参因碰撞变化 | 中 | 地图和定位失效 | 机械标记、赛前检查 | 换备件后重新建图或恢复标定 |
| CPU 过载/温度降频 | 中 | 数据延迟、控制抖动 | headless、降采样、监控 | 降低点云负载和车速 |
| 相对地图路径失效 | 中 | 地图加载失败 | 全部使用绝对路径和校验 | 切换备份地图路径 |

### 最小可交付回退层级

```text
L1：地图定位 + 固定路线 + 避障 + 自主导航（目标方案，系数 1.4）
L2：地图定位 + 固定路线 + 仅停车避障（仍争取按自主导航解释）
L3：自主跟随模式（仅在规则确认可用且 L1/L2 无法安全运行时）
L4：人工遥控保底
```

回退不应临场重写代码，而应通过配置开关和独立启动脚本完成。

## 21. 最终判定

这套方案的核心不是堆叠通用导航组件，而是把最容易失效的五个接口做实：

```text
Airy 原始数据格式
→ 点云/IMU 时间与坐标一致性
→ Lightning 地图位姿可靠性
→ 路线、检查点与局部障碍决策
→ /STEER 及失效停车
```

完成这五个闭环并通过连续重复测试后，S10 即具备决赛所需的现场建图、地图定位、自主导航和避障能力。后续所有提速或增强功能，都应以不破坏这一稳定基线为前提。
